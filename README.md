# HR Multi-Agent — локальный контур

Начальная реализация [БФТ](bft_main.md) для n8n + Python + PostgreSQL. **Автономная отправка выключена по умолчанию.** Включать её можно только после проверки прав конкретного HH-приложения и тестового отклика. Текущий код не охватывает весь БФТ; подробности ниже.

## Запуск

1. Запустить Docker Desktop.
2. Использовать локальный `.env`, задать случайные `POSTGRES_PASSWORD`, `N8N_ENCRYPTION_KEY`, `APP_ADMIN_TOKEN`. Не публиковать `.env`.
3. Выполнить `docker compose up --build -d`.
4. Открыть `http://localhost:5678` и импортировать JSON из `workflows/`. Скорректировать поисковый запрос.
5. Для Telegram заполнить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_USER_ID`, перезапустить контейнер `bot`. Команды: `/status`, `/pending`, `/pause`, `/resume`.

Расписание поиска — 08:00 МСК. Сценарий отправки вызывается раз в минуту, но API отдаёт `disabled`, пока `HH_AUTONOMY_ENABLED=false`. Порт n8n и API доступны только на `127.0.0.1`. БД наружу не публикуется.

## Что реализовано

- Локальный Compose с n8n, PostgreSQL и Python-сервисом.
- Защищённые внутренние HTTP endpoints для поиска, отправки и паузы.
- Дедупликация вакансий, базовые сущности фактов, кластеров, версий резюме, откликов, сообщений и аудита.
- Чистая функция взвешенного сходства и complete-link кластеризации.
- Проверка окна откликов, лимитов 3/60 секунд и 24 часов, сверка с HH перед отправкой, отдельное состояние для неопределённого результата.
- Маршрутизатор HH API → локальный Playwright/Chromium для поиска и чтения вакансий. Явно недоступный метод отклика передаётся браузерному адаптеру; `429`, блокировки и неопределённый результат POST не вызывают повтор через браузер.
- Общий журнал `job_attempts` для попыток отклика независимо от канала.
- Telegram long polling для управления без публичного webhook; задачи `NEEDS_HUMAN` и `NEEDS_RECONCILIATION` отправляются пользователю и доступны через `/pending`.

## Локальная браузерная сессия

Chromium запускается внутри локального контейнера `core`. Для ручного входа на macOS с установленным Google Chrome выполните `python3 -m venv .venv`, `.venv/bin/python -m pip install playwright`, затем `.venv/bin/python -m hr_agent.browser_login`. Откроется Chrome; вход и проверку CAPTCHA выполняет пользователь. После входа нужно сообщить о завершении в терминале нажатием Enter. Сессия сохранится в `browser_profile/storage_state.json`, этот каталог исключён из Git и подключён к контейнеру. Файл содержит авторизационные данные, поэтому доступ к нему должен оставаться только у владельца компьютера.

Параметры `.env`: `BROWSER_ENABLED=true` включает браузерный канал для чтения, `HH_API_APPLY_UNAVAILABLE=false` означает, что недоступность метода отклика API ещё не подтверждена, `HH_BROWSER_WRITES_VERIFIED=false` оставляет браузерные изменения выключенными. Само по себе переключение флагов не реализует отправку: селекторы, подтверждение результата и допустимость сценария HH требуют проверки на аккаунте и в браузере.

## До включения автономной отправки

Нужно реализовать и проверить HH OAuth с обновлением токенов, актуальные права и параметры endpoint отклика, создание/публикацию HH-резюме, точное архивирование отправленного пакета, доказуемую связь фактов с исходниками, полную синхронизацию Drive, классификацию сообщений, обработку анкет и CAPTCHA, мониторинг приглашений, резервные копии и миграции схемы. **Не включать `HH_AUTONOMY_ENABLED` до выполнения этих пунктов.**

Текущий `HHClient` — адаптер для проверки API, а не подтверждение работоспособности мутаций на вашем аккаунте. Браузерные отклики, анкеты, сообщения и резюме пока не реализованы; такие задачи переводятся в `NEEDS_HUMAN`, а неопределённые результаты — в `NEEDS_RECONCILIATION`. В БФТ условием является доступ конкретного приложения и соблюдение правил HH.
